## 1. Постановка

Метрика организатора — **macro-F1 по 4 меткам**, каждая метка есть объединение (OR)
своих критериев:

| метка | критерии |
|---|---|
| укладка | `spine_positioning` OR `femur_positioning` |
| ось | `spine_axis` |
| предметы | `spine_artifacts` |
| ROI | `femur_roi` |

Протокол оценки (честный, одинаковый для всех экспериментов):
только реальные снимки (синтетика исключается); 20 разбиений `StratifiedGroupKFold`
по `study_uid`; порог подбирается **только по train-части** фолда; метрика — по
объединённым val-предсказаниям.

## 2. Что НЕ сработало (проверено, чтобы не повторять)

По результатам парных прогонов на 20 разбиениях:

- признаки малого вертела для бедра (`femur_trochanter_bulge`, `femur_troch_area_mm2`,
  `femur_neck_width_mm`) — **хуже** базы (0.507 → 0.47–0.49);
- для оси признаки `spine_axis_angle`, `spine_iliac_signal`, `spine_midline_residual`
  в **чистой геометрии** — хуже (0.45–0.48);
- ансамбль рангов CNN+геометрия — не лучше базы;
- дополнительные признаки укладки (`spine_top_cut`, отступы) — без выигрыша.

Вывод: **признаки уже насыщены**, перебор признаков сам по себе метрику не поднимает.

## 3. Что сработало (подтверждено парно)

Ключ — формулировка из материалов репозитория: *«AUC оси 0.82, а F1 0.42 —
ранжирование хорошее, а решение по порогу плохое»*. То есть запас не в измерении,
а в том, **как признак попадает в модель и в решение**.

| улучшение | Δmacro-F1 | выигрыш |
|---|---|---|
| `spine_axis`: в гибрид добавлен `spine_midline_residual` | +0.049 | **20/20** |
| `spine_artifacts`: источник `fused` вместо `cnn` | +0.007 | 15/20 |
| **v3 = оба** | **+0.056** | **19/20** |

`spine_midline_residual` — остаточная кривизна средней линии позвоночника
(отклонение от прямой). Она позволяет гибридной модели оси отличить «наклон от
прямой оси» от «физиологического изгиба», из-за чего ранжирование оси становится
разделяющим: F1 метки «ось» растёт с 0.42 до 0.62.

## 4. Как применить (2 строки в `config.py`)

Ничего в логике менять не нужно: `stack.py` уже поддерживает
`CRITERION_FEATURES_OVERRIDE` и `CRITERION_SOURCES`. В `dxa_qc/src/config.py`:

```python
# было: "spine_artifacts": "cnn"
CRITERION_SOURCES = {
    "spine_positioning": "cnn",
    "spine_axis": "fused",
    "spine_artifacts": "fused",   # v3: геометрия помогает и здесь
    "femur_positioning": "geo",
    "femur_roi": "cnn",
}

# новое: гибрид оси использует остаточную кривизну
CRITERION_FEATURES_OVERRIDE = {
    "spine_axis": ["spine_midline_angle", "spine_midline_residual"],
}
```

После этого пересобрать стекер и пороги:
`python -m src.stack` и `python -m src.calibrate` (или наш `build_v3.py`).

### Консультация с внешним советником (GPT 6 Astra) и проверка его идей

Astra подтвердил: упор в качество измерений, а не в решающий слой. Приоритеты и их
честная проверка:

| идея Astra | что сделано | результат |
|---|---|---|
| **P1** прямые измерения «посторонних предметов» (`foreign_body` + асимметрия/интенсивность/вытянутость) | `feat_foreign.py` (11 признаков), тест `exp_artifacts.py` | **отклонено**: AUC предметов 0.700 → 0.48–0.62, macro-F1 −0.011…−0.034 |
| **P5** диагностика потолка бедра | `diag_femur.py` | подтвердила: одиночные признаки бедра AUC<0.55; FP связаны с широкой шейкой (41 мм против 35 у нормы) |
| **P2** чистая маска бедра (отделение таза эрозией) + нормировка на головку | `feat_femur2.py`, тесты `exp_femur2.py`, `exp_femur3.py` | **отклонено для F1**: AUC бедра 0.566 → 0.676 (+0.110), AP 0.274 → 0.397, но macro-F1 не растёт (0.553–0.563); совместный оракульный свип порогов даёт укладку F1 0.500 против 0.511 у базы |
| P3 (убрать синтетический металл из artifact-головы CNN) | — | требует переобучения CNN, а оно доказанно хуже базового |
| P4 (синтетика в стекер) | — | высокий риск домен-сдвига, отложено |

**Вывод по P1:** критерий «предметы» упирается не в отсутствие прямого измерения, а в
шум метки: даже прямые измерения артефактов не переносятся на организаторскую разметку.
Геометрия `ribs+peaks` в гибриде остаётся лучшей.

**Вывод по P2 (важный):** измерение бедра действительно улучшилось — отделение таза
эрозией и нормировка на диаметр головки подняли AUC критерия 0.566 → 0.676 и AP
0.274 → 0.397 (подтверждает гипотезу «FP = слияние с тазом»). Но в **F1 это не
переходит**: при развёрнутом правиле порога macro-F1 не растёт, а совместный
оракульный свип порогов для «укладки» даёт даже чуть хуже (0.500 против 0.511).
Улучшение ранжирования пришлось на участок ROC, не влияющий на F1-оптимальную точку.
**Урок:** при малых данных и разбалансе AUC — плохой ориентир; оптимизировать надо
точность в окрестности рабочего порога.

### Остаток нерешённого

Метка «укладка» (0.496) упирается в `femur_positioning`: recall 0.81, но precision
всего 0.37 (55 ложных срабатываний на 150 снимках бедра). Порог это не лечит
(oracle-порог даёт ту же F1). Нужен более разделяющий сигнал ротации бедра —
кандидат для дообучения на большей выборке.

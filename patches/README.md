# Патч к решению dxa_qc: масштаб снимка, измерение оси, поддержка синтетики

Готовые файлы лежат в `../dxa_qc/src/`, патч — `01_pixel_spacing_and_midline.patch`.

Три группы изменений:
1. реальный размер пикселя из тега Exposed Area (раздел ниже);
2. новый признак `spine_midline_angle` — измерение оси так, как смотрит врач;
3. поддержка синтетических снимков: они идут только в обучение и исключаются из метрик,
   подбора порогов и отчёта (см. [docs/synthetic.md](../docs/synthetic.md)).

## Проблема

В `config.py` размер пикселя задан константой:

```python
PIXEL_SPACING_MM = (0.6, 1.05)   # (x, y)
```

От неё зависят все углы в `features.py`. Но в файлах набора есть тег **(0040,0303) Exposed Area** — физический размер снятой области в миллиметрах. Он присутствует **во всех 499 файлах**, и деление на размер кадра даёт настоящий масштаб каждого снимка:

| | медиана | разброс |
|---|---|---|
| мм на пиксель по X | 0.607 | 0.58–0.62 |
| мм на пиксель по Y | 0.608 | 0.58–0.62 |

Пиксель **квадратный**. Прежнее соотношение 1.05/0.6 занижало все углы в **1.75 раза**: наклон оси 5° измерялся как 2.9°.

Последствия:
1. Пороги ТЗ в градусах и сантиметрах применить было нельзя.
2. Утверждение в документации, что признаки «пересчитаны в физические единицы», не выполнялось.
3. На закрытом тесте, где кадры могут быть другого размера, константа даёт систематический сдвиг, а тег — нет.

## Что меняет патч

| Файл | Изменение |
|---|---|
| `config.py` | Константа → запасное значение (0.6, 0.6); добавлены `EXPOSED_AREA_TAG`, `PIXEL_SPACING_LIMITS` |
| `dicom_io.py` | Новая функция `pixel_spacing(ds, arr)` — масштаб из Exposed Area с отсевом мусорных значений |
| `dataset.py` | В манифест пишутся колонки `spacing_x`, `spacing_y` |
| `features.py` | Все угловые признаки принимают `spacing`; `build_features` берёт его из манифеста |
| `features.py` | **Новый признак `spine_midline_angle`** — угол по средней линии позвоночного столба |
| `stack.py` | Критерий `spine_axis` использует новый признак |
| `inference.py`, `api.py` | Масштаб снимка передаётся в расчёт признаков при инференсе |
| `dataset.py` | Колонка `synthetic` и функция `real_mask()` |
| `train.py` | Метрики и выбор лучшей эпохи — только по реальным снимкам |
| `stack.py`, `calibrate.py`, `report.py` | Стекер, пороги и отчёт считаются только по реальным снимкам |

### Про новый признак

`spine_axis_angle` считает главную ось всей яркой области, и её «тянет» вертикальная протяжённость кадра. Врач смотрит на линию через центры тел позвонков. Новый признак строит именно её:

| Признак | AUC по метке «ось не выровнена» |
|---|---|
| `spine_axis_angle` (было) | 0.733 |
| гибрид CNN + геометрия (в отчёте команды) | 0.690 |
| **`spine_midline_angle` (стало)** | **0.861** |

Значения совпали со шкалой ТЗ: при нарушении медиана 4.9°, в норме 2.5° (в ТЗ примеры 6.9° и 1.6°). Правило «наклон > 5°» без всякого обучения даёт чувствительность 0.50 при специфичности 0.85.

## Как применить

Вариант 1 — взять готовые файлы из `../dxa_qc/src/`.

Вариант 2 — наложить патч (файлы с CRLF, поэтому нужен `--ignore-whitespace`):

```bash
git apply -p2 --ignore-whitespace patches/01_pixel_spacing_and_midline.patch
```

## Что перезапустить

Нейросеть переобучать **не нужно**: она работает с изображениями, а изменились только геометрические признаки.

```bash
# 1) пересобрать манифест (добавятся колонки spacing_x, spacing_y)
python -c "from src import dataset; dataset.build_manifest(r'ПУТЬ\НД_для_обучения')"

# 2) удалить старые признаки, они посчитаны в неверном масштабе
del artifacts\features.csv

# 3) пересчитать стекер, пороги и отчёт
python -m src.stack
python -m src.calibrate
python -m src.report
```

## Как добавить синтетические нарушения

```bash
python scripts/make_synthetic_for_dxa_qc.py --dataset C:\dxa --project dxa_qc --per-type 40
python -m src.train
python -m src.stack && python -m src.calibrate && python -m src.report
```

Скрипт кладёт синтетические изображения в кэш и дописывает строки в манифест с `synthetic=True`.
На нашей схеме оценки это дало AUC 0.702 → 0.838 по области интереса бедра и 0.548 → 0.767
по укладке позвоночника.

## Чего патч НЕ даёт

Само по себе исправление масштаба почти не меняет AUC существующих признаков: преобразование почти монотонное, а AUC зависит только от порядка. Выигрыш даёт новый признак и возможность применять пороги ТЗ. Проверено на 252 снимках набора.

# DXA-QC — ИИ-сервис контроля качества денситометрических исследований

Сервис автоматически оценивает качество рентгеновских денситометрических
исследований (DXA) и корректность разметки анатомических структур. Для каждого
изображения определяется анатомическая область, бинарный класс качества
(`качественное` / `есть нарушение`) и типы выявленных нарушений, а результат
сохраняется в структурированный файл `xlsx/csv`.

> Решение полностью локальное: медицинские изображения не передаются во внешние
> системы.

---

## 1. Назначение, возможности и ограничения

### 1.1 Основные возможности

- чтение исследований в формате DICOM (одно исследование — одна или несколько серий);
- дедупликация изображений внутри исследования;
- автоматическое определение анатомической области:
  - поясничный отдел позвоночника (`lumbar_spine`);
  - проксимальный отдел левого бедра (`proximal_femur_left`);
  - проксимальный отдел правого бедра (`proximal_femur_right`);
- бинарная классификация качества (`quality_class`);
- мультилейбл-определение типов нарушений (`violation_type`);
- формирование отчёта в формате `csv`/`xlsx` со структурой из ТЗ;
- пакетная обработка каталога исследований;
- REST API для интеграции;
- визуализация объяснений (Grad-CAM) — дополнительный функционал.

### 1.2 Таксономия нарушений

Внутренние коды критериев и их значения в выходном поле `violation_type`
(закрытый список организатора):

| Внутренний код | Область | Значение `violation_type` |
|---|---|---|
| `spine_positioning` | поясничный отдел | `Некорректная укладка` |
| `spine_axis` | поясничный отдел | `Не выравнена ось позвоночника` |
| `spine_artifacts` | поясничный отдел | `Присутствуют посторонние предметы` |
| `femur_positioning` | проксимальный отдел бедра | `Некорректная укладка` |
| `femur_roi` | проксимальный отдел бедра | `Некорректная область интереса` |

Описания критериев: нарушение укладки (не визуализируются верхние края
подвздошных костей / половина Th12); отклонение оси позвоночника > 5°;
посторонние предметы/артефакты/наложения; нарушение позиционирования/ротации
бедра; некорректная область интереса (ROI).

> Требования к формату вывода уточнены организатором в документе
> «Разъяснения по вопросам ЛЦТ» (ред. V2): русские значения закрытого списка,
> разделитель `;`, пустое поле при отсутствии нарушений, колонка `quality_prob`
> в диапазоне [0;1], размер пикселя сканера 0.6 × 1.05 мм.

### 1.3 Ограничения

- обучающая выборка мала (100 исследований, 252 уникальных изображения), поэтому
  редкие типы нарушений имеют широкие доверительные интервалы метрик;
- бинарная метка качества формируется агрегацией критериев разметки организатора
  (колонка «Итог»), что вносит шум;
- сторона бедра определяется по геометрии изображения (наклон оси кости), а не по
  DICOM-тегу `Laterality` (в данных он пуст);
- решение не является медицинским изделием и предназначено для поддержки
  контроля качества, а не для постановки диагноза.

## 4. Данные и предобработка

### 4.1 Состав обучающего набора

- `НД_для_обучения/исследования/<study_uid>/series_XXX_N_CR/.../CR00000N.dcm`;
- `НД_для_обучения/разметка.xlsx` — экспертная разметка по критериям;
- 100 исследований, 499 файлов, **252 уникальных изображения** после дедупликации.

### 4.2 Предобработка

1. чтение `pydicom`, извлечение `pixel_array`;
2. дедупликация по содержимому пикселей (устраняет повторы внутри серии);
3. робастная нормировка яркости (перцентили 0.5/99.5) → `uint8`;
4. дополнение до квадрата (сохранение пропорций) и масштабирование до
   `IMAGE_SIZE` = 224×224 (единое значение для обучения и инференса, `config.py`);
5. нормализация в `[0,1]`, приведение к 1 каналу.

### 4.3 Разбиение выборки

Используется `GroupKFold` по `study_uid`: все изображения одного исследования
попадают только в train **или** только в val. Это исключает утечку данных между
выборками (важнейший критерий оценки организатора).

## 5. Модель и постобработка

### 5.1 Архитектура

Мультизадачная сеть на базе `ResNet18` (ImageNet-инициализация), вход — 1 канал:

```
вход (1×224×224)
  └─ ResNet18 backbone → признаки (512)
        ├─ head_region    → 3 класса (анатомическая область)
        ├─ head_quality   → 3 логита (качество по каждой области)
        └─ head_violation → 5 логитов (мультилейбл критериев)
```

- `head_quality` регион-зависима: при обучении/инференсе берётся логит,
  соответствующий истинной/предсказанной области, что повышает точность.
- функция потерь: сумма CrossEntropy (регион) + маскированная BCE (качество) +
  маскированная BCE (нарушения) с весами `pos_weight` для борьбы с дисбалансом.

### 5.2 Постобработка

1. ансамблирование моделей кросс-валидации (усреднение вероятностей);
2. анатомическая область — геометрический детектор + голова классификации;
3. `quality_class = 1`, если вероятность нарушения ≥ порога (калибруется по OOF);
4. список нарушений формируется только из критериев, применимых к области;
5. при `quality_class = 0` список нарушений пуст.

### 5.3 Гибридный подход (CNN + геометрия)

Часть критериев качества измерима геометрически, поэтому поверх нейросети
обучается стекер (логистическая регрессия) `artifacts/stacker.joblib`:

```
[вероятность CNN | геометрические признаки] -> LogReg -> уточнённая вероятность
```

Признаки (`src/features.py`): наклон главной оси кости, вытянутость
(`eccentricity`), доля яркой (костной) площади, горизонтальная асимметрия.
Набор признаков подобран по каждому критерию отдельно (по приросту ROC-AUC на
OOF-CV). Обучение стекера — с `GroupKFold` по `study_uid` (без утечки).
Гибрид применяется к критериям нарушений; класс качества оценивается
нейросетью.

Геометрические величины пересчитываются в физические единицы с учётом размера
пикселя сканера **0.6 мм (X) × 1.05 мм (Y)** (по разъяснениям организатора),
что важно для критерия «отклонение оси позвоночника > 5°».

## 6. Обучение и метрики

```bash
# 1) обучить (GroupKFold + финальная модель).
#    Гиперпараметры по умолчанию (config.py): epochs=24, folds=5, size=224,
#    batch=24, lr=2e-4 — совпадают с инференсом, аргументы можно не указывать.
python -m src.train

#    На другом ПК сначала пересобрать манифест под новый путь к данным:
#    python -m src.train --dataset-root "D:\data\НД_для_обучения" --rebuild-manifest

# 2) обучить гибридный стекер (CNN + геометрия)
python -m src.stack

# 3) подобрать пороги по OOF
python -m src.calibrate

# 4) собрать отчёт с метриками
python -m src.report
```

Метрики (`artifacts/metrics.json`, `artifacts/report.md`): F1, ROC-AUC, PR-AUC,
чувствительность, специфичность, сбалансированная точность; для F1/AUC — 95%
доверительные интервалы (bootstrap). Метрики считаются отдельно по каждой
анатомической области и каждому типу нарушения.

### 6.1 Полученные результаты (GroupKFold, 5 фолдов, n=249)

| Задача | Метрика | Значение |
|---|---|---|
| Качество (бинарно) | F1 / ROC-AUC | 0.526 [0.444, 0.596] / 0.670 [0.593, 0.744] |
| Качество (бинарно) | PR-AUC | 0.525 [0.412, 0.639] |
| Качество (бинарно) | чувствительность / специфичность | 0.836 / 0.443 |
| Определение области | accuracy | 1.000 |
| Типы нарушений (macro-F1, 4 метки организатора) | macro-F1 | 0.471 |

По анатомическим областям (класс качества):

| Область | N | ROC-AUC | F1 |
|---|---|---|---|
| `lumbar_spine` | 99 | 0.616 | 0.559 |
| `proximal_femur_left` | 78 | 0.669 | 0.514 |
| `proximal_femur_right` | 72 | 0.755 | 0.571 |

По типам нарушений (гибрид CNN + геометрия):

| Критерий | N | Pos | ROC-AUC | F1 |
|---|---|---|---|---|
| `spine_positioning` | 99 | 6 | 0.740 | 0.308 |
| `spine_axis` | 99 | 10 | 0.690 | 0.364 |
| `spine_artifacts` | 99 | 17 | 0.703 | 0.453 |
| `femur_positioning` | 150 | 36 | 0.676 | 0.483 |
| `femur_roi` | 150 | 7 | 0.808 | 0.615 |

Гибрид даёт наибольший прирост там, где критерий измерим геометрически:
`spine_axis` (AUC 0.596 → 0.690), `spine_positioning` (0.629 → 0.740),
`femur_roi` (0.664 → 0.808).

Полный отчёт — `artifacts/report.md`, машинночитаемые метрики —
`artifacts/metrics_by_region.json`, сравнение CNN/гибрида —
`artifacts/stack_metrics.json`.

### 6.2 Пороги классификации

Пороги подбираются по OOF-предсказаниям отдельно для каждой области качества
(разброс AUC между областями велик) и для каждого типа нарушения; сохраняются в
`artifacts/thresholds.json` и автоматически используются инференсом:

| Область | Порог качества |
|---|---|
| `lumbar_spine` | 0.07 |
| `proximal_femur_left` | 0.72 |
| `proximal_femur_right` | 0.57 |

Пороги нарушений (гибридная шкала): `spine_positioning` 0.76, `spine_axis` 0.54,
`spine_artifacts` 0.51, `femur_positioning` 0.66, `femur_roi` 0.76.

### 6.3 Честная валидация vs прогон по обучающим данным

Файл `outputs/validation_oof.csv` содержит OOF-предсказания (честная оценка на
невиданных данных). Файл `outputs/results.csv` — прогон финальной модели по
**обучающему** набору; из-за переобучения на нём вероятности смещены вверх, что
ожидаемо и не является показателем качества на тестовом наборе.

## 9. Формат входных и выходных данных

**Вход:** DICOM-файлы (по одному исследованию в каталоге или каталог
`исследования/`).

**Выход:** `csv`/`xlsx`, одна строка — одно изображение (одна анатомическая
область):

| Колонка | Описание | Формат |
|---|---|---|
| `path_to_study` | путь к исследованию/файлу | String |
| `study_uid` | идентификатор исследования | String |
| `image_uid` | идентификатор изображения | String |
| `anatomical_region` | определённая область (см. ниже) | String |
| `quality_class` | 0 — качественное, 1 — есть нарушение | Integer |
| `violation_type` | тип(ы) нарушений (см. ниже) | String |
| `processing_status` | Success / Failure | String |
| `time_of_processing` | время обработки, сек | Float |
| `quality_prob` | вероятность нарушения, [0;1] (доп.) | Float |
| `violation_probs` | вероятности критериев (доп., внутренние) | String |

### 9.1 Значения `anatomical_region` (закрытый список)

| Значение |
|---|
| `Поясничный отдел позвоночника` |
| `Проксимальный отдел бедра` |

Сторона (лево/право) не указывается — по требованию организатора.

### 9.2 Значения `violation_type` (закрытый список)

| Область | Значения |
|---|---|
| Поясничный отдел | `Некорректная укладка`; `Не выравнена ось позвоночника`; `Присутствуют посторонние предметы` |
| Проксимальный отдел бедра | `Некорректная укладка`; `Некорректная область интереса` |

- при нескольких нарушениях значения перечисляются через `; ` (точка с запятой
  с пробелом), например `Некорректная укладка; Некорректная область интереса`;
- при отсутствии нарушений поле **пустое**;
- Macro-F1 считается организатором по этому закрытому списку (4 уникальные
  метки; `Некорректная укладка` общая для двух областей).

## 10. Известные ошибки и их обработка

| Ситуация | Поведение |
|---|---|
| DICOM без пиксельных данных | строка со `processing_status=Failure` |
| битый/нечитаемый файл | перехват исключения, `Failure`, поле `error` |
| нет весов модели | понятная ошибка с инструкцией обучить модель |
| несовпадение числа областей и групп разметки | предупреждение при построении манифеста |
| кириллические пути | запись изображений через PIL (обход проблемы OpenCV) |

## 11. Воспроизводимость

- фиксированный `SEED=42` для всех генераторов случайных чисел;
- зафиксированные версии зависимостей;
- детерминированное разбиение `GroupKFold` по `study_uid`;
- повторный запуск на одинаковых данных даёт идентичные результаты.

## 12. Обучение/дообучение модели

Единые параметры (`config.py`): `IMAGE_SIZE=224`, `epochs=24`, `folds=5`,
`batch=24`, `lr=2e-4` — используются и при обучении, и при инференсе.

```bash
# обучить на текущем датасете (значения по умолчанию)
python -m src.train

# на другом ПК: пересобрать манифест под новый путь к данным и обучить
python -m src.train --dataset-root /path/to/dataset --rebuild-manifest --device cuda

# инференс на GPU
python -m src.predict --input /data --output out.csv --device cuda
```

> Важно: в `artifacts/manifest.csv` прописаны абсолютные пути к данным и кэшу.
> При переносе проекта на другой ПК **обязательно** запускать обучение с
> `--rebuild-manifest` (или предварительно построить манифест заново), иначе
> пути будут указывать на несуществующие файлы.

Быстрый старт (шпаргалка со всеми командами) — `docs/quickstart.md`.
Руководство пользователя и руководство по развёртыванию — в `docs/`.

## 2. Ключевые технические решения

1. **Дедупликация изображений** по содержимому пикселей — 499 файлов → 252
   уникальных изображения.
2. **Восстановление связи «изображение ↔ анатомическая область»** по геометрии
   (ширина ≥ 295 px → поясничный отдел) — точность определения области 100%.
3. **Определение стороны бедра** по наклону главной оси кости (знак наклона);
   правило подтверждено на исследованиях с известной разметкой левого бедра.
4. **GroupKFold по `study_uid`** — исключает утечку данных между train/val
   (изображения одного исследования не попадают одновременно в обе выборки).
5. **Регион-зависимая голова качества** — отдельный логит на каждую область.
6. **Пороги по областям и критериям** (калибровка по OOF) — учитывает разброс
   AUC между областями.
7. **Гибридный стекер (CNN + геометрия)** — к вероятностям сети добавляются
   измеримые геометрические признаки (ось кости, вытянутость, доля костной
   площади), что повышает AUC на `spine_axis`, `spine_positioning`, `femur_roi`.

## 3. Метрики (честная OOF-оценка, n=249)

- Качество: F1 = **0.526** [0.444, 0.596], ROC-AUC = **0.670** [0.593, 0.744].
- Определение области: accuracy = **1.000**.
- Типы нарушений (macro-F1 по закрытому списку организатора, 4 метки) = **0.471**.

### 3.1 Соответствие уточнённому формату вывода (разъяснения V2)

- `anatomical_region` — русские значения: `Поясничный отдел позвоночника`,
  `Проксимальный отдел бедра` (сторона не указывается);
- `violation_type` — закрытый список на русском, несколько нарушений через `; `,
  при отсутствии — пустое поле;
- `quality_prob` — вероятность нарушения в диапазоне [0;1];
- геометрические признаки пересчитаны в физические единицы (пиксель 0.6 × 1.05 мм).

## 5. Текущие ограничения и план доработки

**Ограничения:**

- малая выборка (252 изображения) → широкие ДИ и низкие метрики по редким
  критериям (`spine_axis`, `spine_artifacts`);
- метка качества агрегирована из критериев → шум;
- обучение выполнено на CPU; на GPU качество можно повысить (больше эпох,
  разрешение, тяжёлые аугментации, больше архитектур в ансамбле).

**План доработки:**

1. собрать больше размеченных данных (особенно редких нарушений);
2. добавить разметку локализации (ROI/ключевые точки) → сегментационные метрики;
3. реализовать DICOM SR и интерактивный веб-интерфейс (доп. функционал ТЗ);
4. провести сравнительный эксперимент архитектур (ResNet34/EfficientNet) и
   различных схем аугментации;
5. собрать и протестировать Docker-образ на целевой конфигурации (H200).

# DXA-QC — презентация решения (структура и тезисы)

## Слайд 1. Проблема и цель

- Денситометрия — основной метод оценки минеральной плотности кости.
- Достоверность зависит от укладки, области интереса и разметки.
- Контроль качества сегодня — вручную, субъективно, трудоёмко.
- **Цель:** автоматический цифровой помощник контроля качества DXA с
  объяснением типа нарушения.

## Слайд 2. Понимание клинической задачи

- Области: поясничный отдел позвоночника; проксимальный отдел бедра (L/R).
- Критерии качества:
  - позвоночник — укладка, ось (≤5°), артефакты;
  - бедро — позиционирование/ротация, область интереса.
- Таксономия построена 1:1 по методическим критериям организатора.

## Слайд 3. Данные

- 100 исследований, 499 DICOM-файлов → **252 уникальных изображения**.
- Дедупликация по содержимому пикселей.
- Связь «изображение ↔ анатомическая область» восстановлена по геометрии.
- Сторона бедра — по наклону оси кости (подтверждено на исследованиях с
  известной разметкой левого бедра).
- Дисбаланс: 176 качественных / 73 с нарушением; редкие критерии (6–7
  положительных) — учитывается весами классов.

## Слайд 4. Архитектура решения

- Мультизадачная сеть ResNet18 (1 канал) с тремя головами:
  - область (3 класса), качество (регион-зависимая), нарушения (5 критериев).
- Определение области = геометрический детектор + нейросетевая голова.
- Ансамбль моделей кросс-валидации.
- Гибридный стекер: к вероятностям сети добавляются измеримые геометрические
  признаки (ось кости, вытянутость, доля костной площади).

## Слайд 5. Предотвращение утечки данных

- Разбиение **GroupKFold по study_uid**: изображения одного исследования не
  попадают одновременно в train и val.
- Фиксированный seed, зафиксированные версии — воспроизводимость.

## Слайд 6. Метрики (пример результатов)

- Определение области: accuracy = 1.000.
- Качество: F1 = 0.526 [0.444, 0.596], ROC-AUC = 0.670 [0.593, 0.744].
- Типы нарушений (macro-F1 по закрытому списку организатора, 4 метки) = 0.471.
- Гибрид даёт прирост: `spine_axis` AUC 0.596 → 0.690,
  `spine_positioning` 0.629 → 0.740, `femur_roi` 0.664 → 0.808.
- Отдельно по каждой области и каждому типу нарушения (см. `artifacts/report.md`).

## Слайд 7. Анализ ошибок

- Наибольшие трудности — редкие критерии (мало примеров).
- Пограничные случаи: ось близко к 5°, слабые артефакты.
- Шум в агрегированной метке качества.

## Слайд 8. Продукт

- CLI пакетной обработки → `results.csv/xlsx` в формате ТЗ.
- REST API (FastAPI), локальный, без внешних сервисов.
- Визуализация нарушений (Grad-CAM).
- Docker-контейнер + `run.sh` (Linux/UNIX), CPU и GPU-варианты.
- Вывод строго по уточнённому формату (разъяснения V2): русские значения
  `anatomical_region` и `violation_type` (закрытый список), колонка
  `quality_prob` в [0;1].

## Слайд 9. Системные требования и скорость

- Минимум: 4 ядра, 4 ГБ RAM, без GPU.
- Рекомендуется: 8+ ядер, 16 ГБ RAM, NVIDIA GPU.
- Целевая конфигурация: 2 × H200 (GPU-44-256-H200-1).
- Время обработки одного исследования — в пределах лимита 3 мин.

## Слайд 10. Ограничения и внедрение

- Малая выборка → широкие ДИ по редким классам.
- Требуется дообучение на данных центра.
- Сценарий внедрения: пилот на архиве → контроль качества разметки →
  приоритизация ручного просмотра → масштабирование на поток.

## Демонстрационный сценарий

1. Показать исходное исследование (позвоночник + два бедра).
2. Запустить `python -m src.predict --input <каталог> --output results.csv`.
3. Открыть `results.xlsx`: строки по областям, классы и типы нарушений.
4. Показать тепловую карту Grad-CAM для исследования с нарушением.
5. Запустить API и выполнить запрос `/predict/image`.

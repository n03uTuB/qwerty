# DXA-QC — шпаргалка (быстрый старт)

Короткий ответ на вопросы: **что это, как запустить, какой файл за что отвечает.**
Подробности — в `README.md`.

---

## 1. Что делает сервис

Для каждого снимка DXA выдаёт три ответа:

1. **Что это за область** — поясничный отдел позвоночника или проксимальный
   отдел бедра;
2. **Качество** — `0` (хороший снимок) или `1` (есть нарушение);
3. **Какие нарушения** — из закрытого списка (укладка, ось, артефакты,
   область интереса).

Результат — таблица `csv`/`xlsx` со строкой на каждый снимок.

## 2. Быстрый запуск (Windows, PowerShell)

Открыть терминал и перейти в папку проекта:

```powershell
cd C:\Users\Антон\Desktop\hak\dxa_qc
$env:PYTHONIOENCODING='utf-8'
```

### Прогнать папку со снимками (главная команда)

```powershell

```

Появится:

### Запустить веб-сервис (API)

```powershell

```

Проверка: открыть в браузере `http://localhost:8000/health` → `{"status":"ok"}`.

## 3. Формат результата

Файл `results.csv`, одна строка = один снимок:

| Колонка | Что означает | Пример |
|---|---|---|
| `path_to_study` | путь к исследованию | `...\исследования\1.2.840...` |
| `study_uid` | номер исследования | `1.2.840...` |
| `image_uid` | номер снимка | `1.2.643...` |
| `anatomical_region` | область | `Поясничный отдел позвоночника` |
| `quality_class` | качество | `0` или `1` |
| `violation_type` | нарушения | `Некорректная укладка; Некорректная область интереса` (или пусто) |
| `processing_status` | обработано? | `Success` / `Failure` |
| `time_of_processing` | время, сек | `0.785` |
| `quality_prob` | вероятность нарушения | `0.83` (от 0 до 1) |

Значения `anatomical_region` и `violation_type` — строго из закрытого списка
организатора (см. README, раздел 9).

## 4. Карта файлов (что за что отвечает)

### `src/` — код

| Файл | Простыми словами |
|---|---|
| `config.py` | настройки: пути, список нарушений, размер картинки, русские названия |
| `dicom_io.py` | читает медицинские файлы DICOM, убирает дубли, определяет область |
| `dataset.py` | собирает таблицу снимков с разметкой, готовит данные для сети |
| `model.py` | сама нейросеть (ResNet18 с тремя «головами») |
| `train.py` | обучение модели |
| `features.py` | «линейка»: измеряет геометрию (угол оси, размеры) |
| `stack.py` | гибрид: соединяет нейросеть и геометрию |
| `calibrate.py` | настраивает пороги «хорошо/плохо» |
| `inference.py` | главный обработчик: прогоняет снимки через модель |
| `predict.py` | кнопка запуска (`python -m src.predict`) |
| `api.py` | веб-сервис (REST API) |
| `report.py` | считает метрики качества модели |
| `visualize.py` | картинки-объяснения (Grad-CAM) |
| `demo.py` | демонстрационный прогон |

### `artifacts/` — «выученные знания» (создаются при обучении)

| Файл | Простыми словами |
|---|---|
| `best_model.pt` | мозг модели (веса), ~43 МБ |
| `fold_0..4.pt` | 5 копий модели с разных кусков данных (для надёжности) |
| `manifest.csv` | список всех снимков с разметкой |
| `image_cache/` | кэш подготовленных снимков |
| `features.csv` | геометрические измерения по каждому снимку |
| `stacker.joblib` | правила гибрида «нейросеть + геометрия» |
| `thresholds.json` | пороги «хорошо/плохо» |
| `report.md` | отчёт с метриками |
| `metrics_by_region.json` | метрики для программы |
| `stack_metrics.json` | сравнение «нейросеть» vs «нейросеть + геометрия» |
| `oof_*.npy` | честные ответы модели на проверке |
| `train*.log` | дневник обучения |

## 5. Порядок создания (если обучать заново)

```powershell
python -m src.train                                                     # обучить модель
python -m src.stack                                                     # гибрид
python -m src.calibrate                                                 # пороги
python -m src.report                                                    # метрики
python -m src.predict --input "<папка>" --output outputs\results.csv    # прогон
```

Размер изображения и гиперпараметры обучения заданы в `config.py`
(`IMAGE_SIZE = 224`, `epochs=24`, `folds=5`, `batch=24`, `lr=2e-4`) и
**совпадают для обучения и инференса** — указывать аргументы не нужно.

Первые четыре шага делаются один раз (уже выполнены). Для новых данных
достаточно последней команды.

### На другом ПК (сценарий А — переобучение на том же датасете)

1. Скопировать проект `dxa_qc` **без** `artifacts/image_cache/`,
   `artifacts/manifest.csv`, `outputs/` (они пересоздаются).
2. Скопировать датасет `НД_для_обучения`.
3. Установить зависимости:
   ```powershell
   pip install -r requirements.txt
   pip install torch==2.14.0 torchvision==0.29.0 --index-url https://download.pytorch.org/whl/cpu
   # для NVIDIA GPU: ... --index-url https://download.pytorch.org/whl/cu124
   ```
4. Пересобрать манифест под новый путь к данным и обучить:
   ```powershell
   $env:PYTHONIOENCODING='utf-8'
   python -m src.train --dataset-root "D:\data\НД_для_обучения" --rebuild-manifest --device cuda
   python -m src.stack
   python -m src.calibrate
   python -m src.report
   python -m src.predict --input "D:\data\НД_для_обучения" --output outputs\results.csv
   ```
   Флаг `--rebuild-manifest` обязателен: он пересоздаёт `manifest.csv` и
   `image_cache/` под новые пути (в исходном манифесте прописаны абсолютные
   пути `C:\Users\Антон\...`).

# Решение команды: пересчёт метрик по честной схеме

Пересчёт делает [`dxa_real/compare_team.py`](../dxa_real/compare_team.py) по их же
OOF-предсказаниям (`artifacts/oof_*.npy`). Веса модели не нужны — предсказания уже сохранены.

Снимки сопоставлены по исследованию и порядку съёмки (по `SOPInstanceUID` нельзя: при
дедупликации представителем одного изображения может оказаться другой файл). Качество
сопоставления проверено: у 98% строк значения их признаков совпадают с пересчитанными.
Сопоставлено 249 снимков из 252.

**macro-F1 по нарушениям: 0.370 «как в отчёте» против 0.254 честно.** Потеря около трети
только из-за способа выбора порога.

## Что не так и почему

### 1. Порог подбирается на тех же данных, по которым считается метрика

`train.best_threshold` перебирает 91 значение порога и берёт то, при котором F1 на
OOF-предсказаниях максимален. Затем этот же F1 идёт в отчёт. Порог — такой же обучаемый
параметр, как веса: подбирать его по проверочным данным значит подглядывать в ответы.

Честно: порог выбирается на одних исследованиях, применяется к другим. Разница — в таблице выше.

При 6–10 положительных примерах эффект особенно велик: сдвиг порога на одно деление меняет
F1 вдвое.

### 2. Лучшая эпоха выбирается по тому же валидационному фолду

В `train.run_cv` каждые три эпохи считается AUC на валидационном фолде, и сохраняются веса
лучшей эпохи. Потом предсказания **этого же фолда** идут в OOF и в метрики. Модель выбрана
по тем данным, на которых измеряется.

Это вторая утечка, и её нельзя убрать пересчётом — нужно переобучение. Поэтому даже AUC
в таблице выше остаётся слегка оптимистичным.

Как исправить: выделять внутренний проверочный кусок из обучающей части, либо обучать
фиксированное число эпох.

### 3. «Точность определения области 1.000» — не метрика модели

Метка области в манифесте ставится правилом «ширина кадра ≥ 295 пикселей», и сеть обучается
предсказывать её же. Единица означает «сеть выучила правило», а не «область определяется
правильно». На защите этот пункт лучше переформулировать честно, иначе вопрос от жюри будет
неприятным.

### 4. Доверительные интервалы занижены

Бутстрэп в `train.bootstrap_ci` ресэмплит изображения. Но у одного пациента до трёх снимков,
и они зависимы. Ресэмплить надо исследования целиком, иначе интервал получается уже реального.
В таблице выше интервалы посчитаны по пациентам и заметно шире: например, для области интереса
бедра [0.50; 0.98] — при семи положительных примерах ничего более определённого сказать нельзя.

### 5. Стекер обучен не на тех вероятностях, с которыми работает

`stack.py` обучает логистическую регрессию на OOF-вероятностях одной модели. В `inference.py`
на вход подаются усреднённые вероятности ансамбля из шести моделей, включая `best_model.pt`,
обученную на всех данных. Распределения разные, поэтому калиброванные пороги смещаются.

Как исправить: либо в инференсе использовать только фолд-модели, либо обучать стекер на
вероятностях того же ансамбля.

### 6. Масштаб снимка задан константой

Разобрано отдельно в [findings.md](findings.md): реальный размер пикселя есть в теге
Exposed Area, а константа `(0.6, 1.05)` занижала все углы в 1.75 раза. Патч в `patches/`.

## Что с этим делать: гибрид по критериям

Сравнение по честной схеме, AUC:

| Критерий | Их CNN | Мои измерения | Лучше |
|---|---|---|---|
| Укладка позвоночника | 0.656 | **0.767** | измерения |
| Ось позвоночника | 0.657 | **0.813** | измерения |
| Посторонние предметы | **0.652** | 0.572 | сеть |
| Позиционирование бедра | 0.642 | **0.683** | измерения (после доработки, см. [rotation.md](rotation.md)) |
| Область интереса бедра | 0.795 | **0.838** | измерения |

Объединение обоих источников в одну модель не выигрывает: на 250 снимках лишние признаки
добавляют шум (проверено, AUC «вместе» был между двумя крайними). Выигрывает выбор источника
**под каждый критерий**: среднее AUC около 0.75 против 0.68 у сети.

Практический вывод: геометрия — для оси, укладки, области интереса и ротации бедра; нейросеть —
для посторонних предметов, которые формулой не описать. Это удобно объяснять врачу: где критерий
измерим, показываем число и порог; где нет — тепловую карту сети.

## Как воспроизвести

```bash
python -c "import sys; sys.path.insert(0,'.'); from dxa_real.compare_team import evaluate_team; evaluate_team(r'C:\dxa', r'ПУТЬ\dxa_qc\artifacts')"
```

Нужны только `features.csv` и `oof_*.npy` из их артефактов. Результат сохраняется в
`out/team_honest.json`.

# Находки по данным и решению

Всё проверено на наборе организатора: 100 исследований, 499 файлов, 252 уникальных изображения,
GE Lunar Prodigy Advance.

## Что в данных

| | |
|---|---|
| Исследований с разметкой | 100 |
| Уникальных изображений | 252 (позвоночник 99, бедро 153) |
| Формат | CR, 8 бит, MONOCHROME2, ~280–300 × 235–320 пикселей |
| Теги | `BodyPartExamined`, `Laterality`, `ViewPosition`, `PixelSpacing` — пустые; пол и возраст обезличены |

Положительных примеров крайне мало:

| Критерий | Нарушений / всего |
|---|---|
| Позвоночник: укладка | 6 / 99 |
| Позвоночник: ось | 10 / 99 |
| Позвоночник: посторонние предметы | 17 / 99 |
| Бедро: позиционирование и ротация | 36 / 150 |
| Бедро: область интереса | 7 / 150 |

Это определяет стратегию: нейросети учиться не на чем, выигрывают измерения по критериям ТЗ.

## Находка 1. Реальный размер пикселя лежит в теге Exposed Area

`PixelSpacing` пуст, но **(0040,0303) Exposed Area** хранит физический размер снятой области
в мм и присутствует **во всех 499 файлах**. Деление на размер кадра даёт масштаб каждого снимка:
**0.607 × 0.608 мм — пиксель квадратный**.

В решении было зашито `(0.6, 1.05)`, что занижало все углы в **1.75 раза**.

Что это даёт:
- пороги ТЗ в градусах и сантиметрах становятся применимыми;
- заявление документации о «физических единицах» становится правдой;
- на закрытом тесте с другими размерами кадра масштаб берётся из снимка, а не угадывается.

Само по себе исправление почти не меняет AUC (преобразование монотонное), но без него
нельзя пользоваться пороговыми правилами.

## Находка 2. Ось позвоночника надо мерить по средней линии столба

Признак `spine_axis_angle` считает главную ось всей яркой области, и её «тянет» вертикальная
протяжённость кадра. Врач смотрит на линию через центры тел позвонков.

| Измерение | AUC по метке «ось не выровнена» |
|---|---|
| `spine_axis_angle` (было) | 0.733 |
| гибрид CNN + геометрия (отчёт команды) | 0.690 |
| **`spine_midline_angle` (стало)** | **0.861** |

После исправления масштаба значения совпали со шкалой ТЗ: медиана 4.9° при нарушении против
2.5° в норме (в ТЗ примеры 6.9° и 1.6°). Правило «наклон больше 5°» **без обучения** даёт
чувствительность 0.50 при специфичности 0.85.

## Находка 3. Число копий снимка связано с нарушением

Одно изображение хранится в архиве в нескольких экземплярах. Для бедра:

| | доля нарушений |
|---|---|
| одна копия (n=51) | 0.16 |
| две и более (n=84) | 0.33 |

Отношение шансов 2.7 (p = 0.028), по критерию «позиционирование/ротация» — 3.2 (p = 0.020).
Эффект не объясняется составом исследования: внутри исследований из трёх снимков он тот же.
У позвоночника связи нет.

Правдоподобное объяснение — переснятые или переобработанные исследования. Дедупликация
в текущем решении эту информацию выбрасывает. Использовать стоит как дополнительный признак
с абляцией: на закрытом тесте выгрузка может быть организована иначе.

## Находка 4. Порядок съёмки надёжнее правила по ширине кадра

`InstanceNumber = 1` у позвоночника в 91 исследовании из 95, типичный порядок «позвоночник →
бедро → бедро» (67 из 95). Область сейчас определяется правилом «ширина ≥ 295», а ширины
в наборе всего три (300 — позвоночник, 280 и 248 — бедро). Порядок устойчивее к смене аппарата.

Отдельно: «точность определения области 1.000» в отчёте команды — не метрика, потому что метка
области сгенерирована этим же правилом, и сеть просто выучила правило.

## Находка 5. Сравнение левого и правого бедра одного пациента

Приём из маммографии (асимметрия сторон). Разница признаков между бёдрами убирает влияние
конституции пациента:

| Признак | AUC по «некорректной укладке» |
|---|---|
| `femur_margin_min_cm` — модуль разницы сторон | 0.636 |
| `femur_bone_ratio` — модуль разницы | 0.620 |
| `femur_shaft_deg` — модуль разницы | 0.605 |

Сопоставимо с лучшими «одиночными» признаками и независимо от них, поэтому даёт прибавку в сумме.

## Находка 6. Синтетические нарушения помогают, но только правильные

Из чистых снимков порождаются нарушения: поворот (ось), обрезка кадра (укладка, область
интереса), вклейка металла (посторонние предметы). Подробности и защита от артефактов
генерации — в [synthetic.md](synthetic.md).

| Критерий | AUC без синтетики | AUC с синтетикой |
|---|---|---|
| Область интереса (бедро) | 0.702 | **0.838** |
| Укладка позвоночника | 0.548 | **0.767** |
| Ось позвоночника | 0.785 | **0.813** |
| Итог качества (позвоночник) | 0.554 | **0.672** |
| Посторонние предметы | 0.588 | 0.572 |

Вклейка металла **вредит**: настоящие «посторонние предметы и наложения» выглядят иначе, чем
яркий компактный объект. Обрезка кадра с растягиванием обратно тоже вредила, пока не выяснилось,
что у настоящих нарушений области интереса кадр **меньше по высоте** — генерация противоречила
самому сильному реальному признаку.

Вывод для защиты: синтетика помогает ровно настолько, насколько верна ваша модель нарушения.

## Протокол честной оценки

В текущем решении метрики завышены по двум причинам:
1. лучшая эпоха выбирается по тому же валидационному фолду, из которого берутся OOF-предсказания;
2. порог подбирается максимизацией F1 на тех же OOF.

В `dxa_real/evaluate.py` сделано иначе:
- разбиение `StratifiedGroupKFold` по `study_uid`, повторы с пятью сидами;
- порог подбирается **во вложенной** кросс-валидации внутри обучающей части;
- доверительные интервалы — бутстрэп **по исследованиям**, а не по снимкам;
- синтетика участвует только в обучении и наследует `study_uid` источника.

Дополнительно проверен выбор порога по ожидаемой доле нарушений: помогает частым классам
(ось: F1 0.296 → 0.375), но вредит редким, поэтому по умолчанию оставлен вложенный подбор.

## Находка 7. Ротацию бедра нужно мерить ниже шейки

Самый частый вид брака (36 из 150). Подробности — в [rotation.md](rotation.md).

| Вариант | AUC |
|---|---|
| Прежние признаки (наклон, силуэт) | 0.595 |
| Их нейросеть | 0.642 |
| **Малый вертел как выпуклость ниже шейки + ширина шейки** | **0.683** |
| Итоговое качество бедра (ИЛИ критериев) | 0.527 → **0.698** |

Две ошибки по пути: измерение захватывало головку с шейкой (выступ получался 72 мм вместо
5–15 мм), а модель из шести признаков переобучалась (0.56 против 0.69 у трёх признаков).

## Находка 8. Требование ТЗ к погрешности измерений можно выполнить и доказать

ТЗ п. 3.1 требует погрешности не более 5% для линейных величин и 3° для угловых. Проверка
сделана поворотом и обрезкой реальных снимков на известную величину
(подробности — [validation.md](validation.md)):

| Величина | Средняя ошибка | В допуске ТЗ |
|---|---|---|
| Угол наклона оси | 0.23° | 100% |
| Ширина шейки бедра | 0.1% | 100% |
| Ширина диафиза | 6.8% | 68.8% — признак отброшен |

Поверка заодно отсеяла неустойчивый признак: ширина диафиза зависит от кадрирования и на
закрытом тесте подвела бы.

## Ограничения

- Метрики получены на 252 снимках одного аппарата; доверительные интервалы широкие.
- Измерения настроены на GE Lunar Prodigy Advance; на другом аппарате пороги надо перепроверить.
- Связь выступа малого вертела с ротацией немонотонная (плохо и слишком мало, и слишком много);
  в этих данных преобладает переротация, на другом наборе понадобится U-образная зависимость.
- Набор признаков для ротации выбран перебором по кросс-валидации, поэтому содержит небольшой
  оптимизм.
- Связь с числом копий может не воспроизвестись на закрытом тесте.

# DICOM-песочница (`dxa_sandbox/`)

Каркас сервиса: чтение DICOM со всеми ловушками формата, извлечение разметки аппарата,
проверки качества и выдача результата в формате [«Базовых функциональных требований» ЦДТ](https://mosmed.ai/ai/docs/)
(версия от 15.09.2026). Работает на синтетическом фантоме — это заготовка и демонстрация
формата, а работа с реальным набором организатора лежит в `dxa_real/`.

## Команды

```bash
# файлы с типичными ловушками формата
.venv\Scripts\python.exe -m dxa_sandbox samples data/samples
```

```bash
# разведка папки: out/inspect/report.html + summary.csv
.venv\Scripts\python.exe -m dxa_sandbox inspect <папка>
```

```bash
# проверки -> доп. серия, DICOM SR, JSON-сообщения в out/qc/<study>/
.venv\Scripts\python.exe -m dxa_sandbox qc <папка>
```

Ещё есть `dump` (теги, включая приватные), `render` (PNG или вложенный PDF), `markup`
(разметка из overlay и цветных линий), `synth` (синтетический набор), `evaluate` (метрики),
`benchmark` (synth → qc → evaluate), `send` и `listen` (обмен с PACS).

## Результат по требованиям ЦДТ

| Файл | Требование |
|---|---|
| `*_qc_sc.dcm` | Одна дополнительная серия Secondary Capture (п. 3.4). Вшитая надпись «В исследовательских целях», название и версия сервиса, дата. Теги прил. 7: `SeriesInstanceUID` по маске `{OriginalSeriesUID}.{modelId}.{addId}.{count}`, `InstitutionName`, `InstitutionalDepartmentName`, `AcquisitionDate/Time`, `OperatorsName=AI` |
| `qc_report_sr.dcm` | DICOM SR с 14 полями в порядке п. 3.3, включая «Технологические дефекты при выполнении исследования» |
| `dicom_report_notify.json` | Сообщение о результате (прил. 4.1) |
| `pum_consumer_error.json` | Сообщение об ошибке (прил. 5.1), категории п. 3.5 |
| `qc_report.json` | Подробный отчёт и самопроверка соответствия формату |

Модальность дополнительной серии переключается флагом `--integration pum|mosmedii`.

## Типы нарушений

Формулировки взяты из п. 3.1 требований ЦДТ: некорректный выбор границ исследования,
нарушение укладки и позиционирования, артефакты от инородных тел, некорректные
физико-технические параметры. Добавлены две группы: ошибки разметки (нумерация позвонков,
положение ROI) и неполные данные DICOM.

## Мини-PACS

```bash
docker compose up -d
```

Веб-интерфейс Orthanc: http://localhost:8042/ui/app/. Демонстрация «как в больнице»:

```bash
.venv\Scripts\python.exe -m dxa_sandbox listen --qc --send-back http://localhost:8042
```

Затем в Orthanc отправить исследование на узел `dxaqc`: сервис примет файлы, проверит их
и вернёт в то же исследование серию с разметкой и SR.

## Состав

| Модуль | Назначение |
|---|---|
| `reading.py` | Чтение DICOM: сжатие, Modality LUT, окно, MONOCHROME1, цвет, мультикадры, размер пикселя, вложенный PDF |
| `inspection.py` | Разведка папки, HTML и CSV, дамп приватных тегов |
| `markup.py` | Разметка аппарата: overlay-слои, цветные линии в пикселях |
| `geometry.py` | Пороги, оси, углы, повороты, перевод в мм |
| `qc.py` | Типы нарушений, модель находок, проверки тегов |
| `checks.py` | Проверки по изображению (демо на фантоме) |
| `pipeline.py` | Исследование → проверки → результат, категории ошибок п. 3.5 |
| `writers.py` | Дополнительная серия, SR, JSON-сообщения |
| `compliance.py` | Самопроверка соответствия требованиям |
| `synthetic.py` | Генератор нарушений на фантоме |
| `evaluation.py` | Метрики по типам нарушений |
| `pacs.py` | Отправка и приём по сети DICOM |
| `samples.py` | Файлы с ловушками формата |

Тесты: `.venv\Scripts\python.exe -m pytest -q tests`.

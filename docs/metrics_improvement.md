# Улучшение метрик: что сделано и что измерено

Оценка — **честная**: группировка по `study_uid`, порог выбирается только по
обучающей части, доверительные интервалы — бутстрэп по исследованиям. Метрика №1 —
macro-F1 по критериям ТЗ.

> **Итог итерации 2 (сервис `dxa_qc`, режим развёртывания).** Честная macro-F1 по
> 4 меткам организатора: **0.401 → 0.494** (+0.093), улучшение в 20/20 случайных
> разбиений. `quality_class`: balanced accuracy 0.630 → 0.645, ROC-AUC 0.712.
> Два изменения: (1) источник скора выбирается по критерию (гибрид нужен только оси
> позвоночника), (2) режим порога `prior` → `f1`. Подробности — в разделе
> «Итерация 2» в конце. Раздел ниже описывает более ранний геометрический контур
> `dxa_real` и остаётся в силе по выводам о признаках.

Воспроизведение:

```powershell
python scripts/final_compare.py --root <dataset_root>     # наборы признаков
python scripts/tune_threshold.py --root <dataset_root>    # стратегии порога
cd dxa_qc; python ../scripts/verify_dxa_qc_metrics.py     # сверка сервиса с эталоном
```

## Главный вывод

Метрику здесь двигает **геометрия, а не сеть**. Критерии ТЗ — измеримые величины
(угол оси по средней линии, отступы поля сканирования, видимость гребней подвздошных
костей, контур малого вертела). Тяжёлые сети на 252 снимках и 6–36 положительных
примерах переобучаются.

Две ошибки исходного кода:

1. **Широкие наборы признаков разбавляли сильные измерения.** Для оси позвоночника
   один признак `spine_midline_deg` давал AUC 0.83, а модель на трёх признаках — 0.78.
2. **Мусорный тег масштаба давал утечку.** У части файлов `Exposed Area (0040,0303)`
   равен константе `[520,478]` → масштаб 1.7–1.9 мм вместо настоящих 0.60–0.65, и все
   сантиметры/площади завышались втрое. Эти выбросы встречались **чаще у нарушений**,
   т.е. подмешивали метку в признаки. На честных масштабах AUC масштаба по критерию
   «укладка бедра» падает с 0.631 до 0.511 (случайность) — сигнал был фиктивным.

## Изменения

1. **`dxa_real/features.py`, `dxa_qc/src/features.py`** — наборы признаков под каждый
   критерий сведены к минимальным семантически прямым измерениям.
2. **`dxa_real/data.py`, `dxa_qc/src/dicom_io.py`** — отсев мусорных значений тега
   Exposed Area (верхняя граница 1.2 мм); в `dxa_qc` представителем дубля берётся
   файл с масштабом, ближайшим к медианному по исследованию.
3. **`dxa_qc/src/features.py`** — признаки считаются по **сырому** DICOM, а не по
   кэшу с display-LUT. Это убирает перекос train/inference: VOI-LUT — нелинейное
   отсечение окном, и признаки на кэше расходились с теми, что видит инференс.
   Проверено: значения совпадают с эталоном (медиана расхождения ~1e-16).
4. **`dxa_qc/src/stack.py`** — те же наборы признаков для гибридного стека.
5. **`dxa_qc/src/config.py`, `calibrate.py`** — режим порога `THRESHOLD_MODE`
   (`prior` по умолчанию: при 6–36 позитивах порог по F1 неустойчив).
6. **`dxa_qc/src/train.py`** — устранена утечка при выборе лучшей эпохи (выбор по
   внутреннему холдауту внутри обучающего фолда, а не по валидационному, из которого
   берутся OOF); `StratifiedGroupKFold`, AMP, TTA, focal/weighted loss, balanced sampler.
7. **`dxa_qc/src/inference.py`** — TTA, новые признаки, передача `copies`.
8. **`dxa_qc/src/dataset.py`** — Albumentations с fallback; поворот с `REFLECT_101`
   вместо чёрных углов (чёрные клинья ложно имитировали артефакты).
9. **`requirements.txt` / `Dockerfile` / `docker-compose.yml`** — albumentations + timm
   (с fallback), GPU-образ под 2× H200 (CUDA 12.4, NVIDIA Container Toolkit).

## Измеренный результат

Честная схема, 252 реальных снимка, 100 исследований, 5 × 5 folds.

|---|---|---|
| Исходный широкий набор (V0), вложенный порог | **0.352** | — |
| Минимальный набор (V3), вложенный порог | **0.404** | **+15 %** |
| V3, усреднение решений (blend) | **0.462** | **+31 %** |
| V3, порог по доле нарушений (prior) | **0.500** | **+42 %** |

### По критериям (AUC / F1, вложенный порог)

| Критерий | V0 AUC | V3 AUC | V0 F1 | V3 F1 |
|---|---|---|---|---|
| spine: не выравнена ось | 0.776 | **0.817** | 0.207 | 0.207 |

Сервис `dxa_qc` на своих признаках даёт те же AUC (spine укладка 0.783, ось 0.818,

### Что проверено и отброшено

| Идея | Результат |
|---|---|
| Синтетические нарушения | spine-качество растёт, но macro-F1 падает; полезно только для spine-качества |
| HistGradientBoosting | переобучается на малых данных |
| Метаданные `copies` в признаки критериев | macro-F1 0.404 → 0.374 |
| Перебор 10 наборов для укладки бедра | лучший — исходные признаки малого вертела; края поля только вредят |
| Мусорный масштаб (как было) | давал фиктивный сигнал; femur-укладка «0.676» была завышена, честно — 0.552 |

## Важные оговорки

* **Честные числа ниже прежних отчётов.** Прежние 0.526 / AUC 0.676 для качества и
  0.676 для укладки бедра опирались, в том числе, на утечку через мусорный масштаб и
  на подбор эпохи/порога по тем же данным. Здесь эти источники убраны — цифры ниже,
  но им можно верить.
* **`prior` использует распространённость из обучающей части.** На закрытом тесте
  распространённость может отличаться — тогда `blend` (0.462) устойчивее. Оба режима
  доступны через `THRESHOLD_MODE`.
* **Оптимизм выбора признаков.** Наборы выбирались сравнением на той же CV, поэтому
  небольшая доля оптимизма остаётся; она ограничена тем, что признаки выбраны по
  смыслу критерия и сильны по отдельности.
* **Сеть не обучена здесь** (в окружении CPU-сборка torch). Геометрический вклад
  измерен напрямую; для полного прогона сервиса нужен GPU-хост.

# Итерация 2 (сервис `dxa_qc`): источник по критерию + режим порога `f1`

Здесь всё измеряется на OOF сервиса: 252 реальных снимка, 100 исследований, 5 фолдов
`GroupKFold`/`StratifiedGroupKFold` по `study_uid`. Синтетика в обучении участвует, в
метрику не попадает. Числа «честные» — порог подбирается только по train-части фолда,
затем объединяются val-предсказания (как если бы организатор оценил один отложенный
набор), 20 разбиений.

## Наблюдение, изменившее подход

В режиме `prior` порог ставится так, чтобы нарушением стало столько снимков, сколько
их ожидается по доле: `k = round(доля * n)`. Тогда

```
F1 = 2*TP / (n_pos + k),
```

и при фиксированных `n_pos` и `k` **F1 зависит только от того, кто попал в top-k**,
то есть от precision@k. ROC-AUC усредняет по всем порогам и к верхушке списка слеп.
Отсюда парадокс: у `spine_axis` AUC 0.889, а F1@prior всего 0.300 (в top-10 — 3
истинных). Поэтому все решения (набор признаков, источник скора) отбирались по
**F1@prior / Average Precision**, а не по AUC.

## Изменение 1. Источник скора по каждому критерию

Гибридный стекер (CNN + геометрия) применялся ко всем критериям. Проверка по F1@prior
показала, что на бедре он **проигрывает** чистой сети, а нужен только для оси:

| Критерий | CNN | геометрия | гибрид |
|---|---|---|---|
| spine_positioning | 0.667 | 0.167 | 0.667 |
| **spine_axis** | 0.100 | 0.300 | **0.300** |
| spine_artifacts | **0.353** | 0.294 | 0.353 |
| **femur_positioning** | **0.444** | 0.213 | 0.361 |
| **femur_roi** | **0.714** | 0.571 | 0.571 |

(полный OOF, порог prior; стенд `scripts/eval_source_configs.py`, перебор всех 3^5
комбинаций — все 8 лучших дают ровно этот паттерн)

Реализовано в `config.CRITERION_SOURCES`: `"fused"` только для `spine_axis`,
остальные `"cnn"`. Для критериев с источником `"cnn"` стекер не строится —
`inference.py` откатывается на чистую сеть, а `stack_oof_violation.npy` хранит
CNN-шкалу.

## Изменение 2. Режим порога `prior` → `f1`

Проверка на честной схеме (порог по train, метрика по val, 20 разбиений):

| Правило порога | macro-F1 (4 метки) | ст.откл |
|---|---|---|
| `prior` (было) | 0.435 | 0.024 |
| `prior` с запасом alpha=1.5 | 0.437 | 0.014 |
| **`f1` (оптимум F1 на train)** | **0.491** | **0.019** |
| `f1` с верхним порогом при равенстве | 0.474 | 0.033 |
| среднее `prior` и `f1` | 0.476 | 0.020 |

Выигрыш по всем меткам сразу: ось 0.307→0.411, предметы 0.307→0.357,
ROI 0.704→0.750, укладка 0.421→0.444. Причина: `prior` систематически
недопредсказывает долю нарушений на валидации (для оси 0.05–0.10 против истинных
0.15–0.16), теряя recall.

Вывод подтверждён отдельно **полностью вложенной** схемой на геометрии (скоры train
считаются внутри фолда, без переиспользования OOF): `f1` 0.424 против `prior` 0.396
(`scripts/check_threshold_clean.py`).

## Итог (честная оценка, 20 разбиений)

| Вариант | macro-F1 (4 метки) | quality BA | quality macro-F1 |
|---|---|---|---|
| Было: гибрид везде + `prior` | 0.401 ± 0.021 | 0.630 ± 0.011 | 0.633 ± 0.010 |
| Шаг 1: источники по критерию + `prior` | 0.435 ± 0.024 | 0.638 ± 0.013 | 0.641 ± 0.012 |
| **Итог: источники + `f1`** | **0.494 ± 0.018** | **0.645 ± 0.013** | 0.603 ± 0.012 |

Прирост macro-F1: **+0.093**, улучшение в **20/20** разбиениях. `quality_class`
ROC-AUC = 0.712 (max вероятности по критериям области, не зависит от порога).

По меткам организатора (итог): укладка 0.444, ось 0.423, предметы 0.357,
ROI 0.750.

## Что ещё проверено и отброшено

| Идея | Результат |
|---|---|
| «Сырые» одиночные признаки как источник (`scripts/eval_raw_features_honest.py`) | не выигрывают: лучшие замены в пределах шума, на бедре хуже |
| Другие оценки угла оси: Theil-Sen, взвешивание шириной, узкая полоса, крупнейшая кость (`scripts/exp_axis_measure.py`) | все дают то же F1@prior 0.300 — узкое место не в измерении, а в перекрытии метки |
| Чистая геометрия вместо гибрида для оси | эквивалентно гибриду (0.354 против 0.354 на 30 разбиениях) — оставлен гибрид |
| Калибровка вероятностей | в режиме `prior` бесполезна (монотонна); при `f1` порог подбирается прямо по F1 |

## Оговорки

* **Числа в `artifacts/report.md` оптимистичны** при режиме `f1`: порог подбирается
  по тем же OOF, по которым считается метрика (в отчёте macro-F1 0.568 против
  честных 0.494). Честная оценка — `scripts/eval_honest_organizer.py`,
  `scripts/eval_final.py`, `scripts/eval_before_after.py`.
* `quality_class macro-F1` слегка снизилась (0.641 → 0.603): порог `f1` срабатывает
  чаще, а `quality_class = ИЛИ(критериев)` становится оптимистичнее. Balanced
  accuracy при этом выросла (0.638 → 0.645), а главная метрика (macro-F1 по 4 меткам)
  выросла сильно.
* Оговорка про распространённость на закрытом тесте остаётся: `f1`-порог подстраивается
  под обучающую часть, что на честной CV оказалось лучше, но при сильном сдвиге
  распространённости `prior` может оказаться устойчивее.

# Синтетические нарушения из реальных снимков

Модуль [`dxa_real/synth_real.py`](../dxa_real/synth_real.py). Скрипт для пайплайна команды —
[`scripts/make_synthetic_for_dxa_qc.py`](../scripts/make_synthetic_for_dxa_qc.py).

## Зачем

Положительных примеров 6–10 на критерий. Учить на этом нечего, а разметить больше некому.
Берём снимки, у которых эксперт не нашёл нарушений, и портим их контролируемо — так, чтобы
результат попадал в диапазон настоящих нарушений.

## Главный риск и защита от него

Модель может выучить **следы преобразования**, а не нарушение: чёрные углы после поворота,
сглаживание интерполяцией, изменившийся размер кадра. Тогда на реальных данных она не сработает.

Что сделано:

1. **Поворот без чёрных углов** — края достраиваются краевыми пикселями (`mode="nearest"`).
2. **Контрольные негативы** — те же чистые снимки проходят ту же обработку с малым углом
   (0.5–2°) и остаются с меткой 0. След поворота есть у обоих классов, поэтому по нему
   классы не разделяются.
3. **Целимся в реальное распределение.** Поворот подбирается так, чтобы ИЗМЕРЕННЫЙ наклон
   стал равен случайной величине из диапазона реальных нарушений (4.5–9°), а не «побольше».
   Проверка: медиана синтетики 5.2° против 5.0° у настоящих нарушений.
4. **Синтетика наследует `study_uid` источника** и потому остаётся в той же части
   кросс-валидации. Метрики считаются только по реальным снимкам.

## Что генерируется

| Вид | Как | Метка |
|---|---|---|
| `axis` | поворот до целевого наклона | Не выравнена ось позвоночника |
| `spine_crop` | обрезка низа кадра (не видны гребни подвздошных костей), кадр растягивается обратно | Некорректная укладка |
| `femur_fov` | обрезка края кадра **без** растягивания: поле сканирования реально меньше | Некорректная область интереса |
| `control` | тот же поворот, но в пределах нормы | нет нарушений |
| `metal` (выключено) | вклейка яркого объекта в мягкие ткани | Присутствуют посторонние предметы |

## Результаты

Честная кросс-валидация, оценка только по реальным снимкам:

| Критерий | AUC без | AUC с | F1 без | F1 с |
|---|---|---|---|---|
| Область интереса (бедро) | 0.702 | **0.838** | 0.500 | 0.294 |
| Укладка позвоночника | 0.548 | **0.767** | 0.138 | 0.370 |
| Ось позвоночника | 0.785 | **0.813** | 0.250 | 0.296 |
| Итог качества (позвоночник, ИЛИ критериев) | 0.554 | **0.672** | 0.485 | 0.571 |
| Итог качества (бедро, ИЛИ критериев) | 0.527 | 0.556 | 0.403 | 0.419 |
| Посторонние предметы | 0.588 | 0.572 | 0.261 | 0.222 |

F1 по редким классам скачет: при 7 положительных примерах порог неустойчив, поэтому судить
лучше по AUC.

## Две неудачи, которые стоит рассказать на защите

**Вклейка металла ухудшила результат** (0.588 → 0.479 в первой версии). Причина: детектор
срабатывает на синтетических объектах и почти не срабатывает на настоящих. Значит, реальные
«посторонние предметы и наложения» выглядят иначе — снимки пересвечены, плотная кость сама
упирается в максимум яркости, и «ярче кости» не существует. Генерация выключена.

**Обрезка кадра для бедра сначала тоже ухудшила** (0.702 → 0.526). Причина: я обрезал кадр
и растягивал обратно, сохраняя размер, а у настоящих нарушений области интереса кадр
**меньше по высоте** — это самый сильный реальный признак. Синтетика прямо противоречила ему
и «переучивала» модель. После отказа от растягивания стало 0.838.

Вывод: синтетика работает ровно настолько, насколько верна модель нарушения. Проверять надо
не только метрику, но и совпадение распределений измерений с реальными нарушениями.

## Как запустить

```bash
# сравнение с синтетикой и без (в этом проекте)
python -c "import sys; sys.path.insert(0,'.'); from dxa_real import ..."
```

Для пайплайна команды:

```bash
python scripts/make_synthetic_for_dxa_qc.py --dataset C:\dxa --project dxa_qc --per-type 40
python -m src.train
python -m src.stack && python -m src.calibrate && python -m src.report
```

Скрипт дописывает строки в `artifacts/manifest.csv` с колонкой `synthetic=True`. Патч к коду
команды исключает такие строки из метрик, подбора порогов и отчёта.


## Измеренная проверка сгенерированной синтетики

Сгенерировано 200 снимков (80 контролей + по 40 ось / укладка позвоночника / ROI бедра)
на 100 исследованиях; 14 точных дубликатов отброшено. Проверка по признакам
(scripts/check_synthetic.py): медианы синтетики должны совпадать с настоящими нарушениями.

| Признак | реальная норма | реальное нарушение | синтетика | контроль |
|---|---|---|---|---|
| `spine_midline_angle` (ось, °) | 2.47 | 5.10 | 7.19 | 2.35 |
| `spine_iliac_signal` (укладка) | 0.162 | 0.000 | 0.000 | 0.193 |
| `femur_height_cm` (ROI) | 17.3 | 12.5 | 15.6 | 17.5 |

Выводы:
* укладка позвоночника и ось воспроизводятся точно (медианы совпадают с реальными);
* ROI бедра получился мягче настоящего (15.6 см против 12.5) — синтетика подсказывает
  направление, но не заменяет редкие настоящие примеры (их всего 7);
* контрольная группа по всем признакам неотличима от нормы — значит сеть не сможет
  выучить след преобразования вместо нарушения.

Отделимость синтетического нарушения от контроля по признакам критерия
(AUC): ось 0.97, укладка 0.96, ROI 0.71. Это ожидаемо — признак и есть критерий;
защита от «выучивания артефакта» обеспечивается контрольной группой, а не слабой
отделимостью.
